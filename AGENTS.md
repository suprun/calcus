# AGENTS.md

Інструкції для ШІ агента, що працює з цим репозиторієм.

## Загальні правила

- Перед змінами уважно перевіряй релевантні файли проєкту.
- Не змінюй сторонні файли без прямої необхідності.
- Для пошуку по коду використовуй швидкі інструменти на кшталт `rg`, якщо вони доступні.
- Тримай зміни мінімальними й прив'язаними до конкретного запиту.
- Відповідай українською мовою.
- Пиши код у стилі, який уже використовується в проєкті.
- Не змінюй архітектуру без явної потреби.
- Не видаляй існуючий функціонал без пояснення.
- Перед великими змінами коротко пояснюй план.

## Навігація репозиторієм

- Перед дослідженням коду прочитай [STRUCTURE.md](STRUCTURE.md), щоб визначити потрібну сторінку, її ресурси та спільні компоненти.
- Починай читання й пошук через `rg` з файлів і папок, релевантних задачі за цією картою; розширюй пошук лише за потреби.
- Після додавання, перенесення або видалення сторінок і ресурсів актуалізуй дерево та таблицю залежностей у `STRUCTURE.md`.

## Створення сторінок калькуляторів

- Перед створенням сторінки прочитай `STRUCTURE.md` і переглянь найближчий за функціональністю наявний калькулятор.
- HTML розміщуй у корені; індивідуальні стилі, скрипти, іконки, дані та документи — у `assets/<назва HTML без розширення>/`.
- Спільні ресурси перевикористовуй з `assets/shared/`. Підключай спільний CSS перед індивідуальним; зміни спільних компонентів не повинні порушувати інші сторінки.
- Зберігай компактне оформлення: `.app`, шапка `.top`, назва, короткий опис, іконка, перемикач теми та панель калькулятора. Використовуй наявні класи полів, кнопок, перемикачів і результатів замість дублювання стилів.
- Індивідуальні CSS-правила обмежуй класом відповідної сторінки. Кольори, межі й радіуси бери зі спільних CSS-змінних; підтримуй світлу, темну та мобільну версії, вертикальне прокручування.
- Перед шапкою всередині `.app` додавай `<a class="home-link" href="index.html">← На головну</a>`.
- Для нових калькуляторів використовуй `assets/shared/theme.js` і кнопку `themeBtn`; не дублюй обробник теми. Скрипти підключай після потрібної розмітки.
- Використовуй спільний favicon `assets/shared/favicon.svg` та окремі SVG-файли через `<img>` або CSS `url()`. Не вбудовуй SVG-геометрію, спрайти й SVG data URL у HTML, JavaScript або CSS.
- Стилі й логіку зберігай у зовнішніх файлах; inline-стилі залишай лише для значень і станів, якими динамічно керує JavaScript.
- Використовуй українську мову, UTF-8, `lang="uk"`, унікальні ID, пов'язані з полями підписи, одиниці вимірювання та доступні назви кнопок.
- Оновлюй результат при зміні параметрів; перевіряй допустимість введення й показуй зрозумілі помилки. Для дробового введення підтримуй кому та крапку.
- Наводь джерела формул і коефіцієнтів; явно позначай припущення та обмеження розрахунку.
- Використовуй відносні шляхи, сумісні з розміщенням у підпапці. Основний розрахунок і локальні ресурси мають працювати через `file://`; функції, яким потрібен HTTP або мережа, документуй.
- Після додавання калькулятора додай посилання й короткий опис у `index.html`, онови дерево та таблицю залежностей у `STRUCTURE.md`.
- Перед завершенням перевір локальні шляхи, синтаксис, початкові й граничні значення, помилкове введення та вплив спільних змін на інші калькулятори. Дотримуйся чинного правила репозиторію щодо браузерної перевірки.

## Стиль коду

- JavaScript: дотримуйся Airbnb Style Guide.
- Назви змінних мають бути зрозумілими.
- Не додавай зайві абстракції.

## Коментарі

- Коментуй тільки неочевидну логіку.
- Не пиши коментарі типу `# increment counter`, якщо дія очевидна з коду.

## Безпека

- Не виводь секретні дані в лог.

## Правила роботи з промптами

- Plan mode: / планування: - режим планування без редагування коду
- Ask mode: / запитання: - режим відповідей на запитання асистентом без редагування коду

## Git

- Не змінюй файли, які не стосуються задачі.
- Не форматуй увесь проєкт без потреби.
- Уникай великих не пов’язаних між собою змін.

## Дані, які не треба редагувати, а лише використовувати за потребою

- calc.html не редагувати, а використовувати як референс, якщо на нього вказується в задачі для отримання ідей чи рішень.
